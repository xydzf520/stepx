# StepX Companion 0.2.50

从 GitHub **0.2.25** 升级：这次重点是让 Amoo 从一次问答变成可以继续修改、预览和交付的会话，同时补齐相册、日程、连接恢复与手机伴侣体验。

## 实测性能

Linux + PZ261A，同一 USB、每项每版 9 次测量：Amoo 连续会话读取中位耗时 **730 → 345 ms（减少约 53%）**；电话基础信息读取 **402 → 275 ms（减少约 31%）**。启动基本持平。以上为预热后的读取路径，不代表模型生成或整个应用提速。[完整方法与逐次数据](https://github.com/xydzf520/stepx/blob/main/docs/PERFORMANCE_0_2_50.md)。

## 核心更新

- **Amoo 会话与连续创作**：回复支持流式接收；按需求识别聊天、文件、图片与应用任务，也可以改回普通聊天。成果卡片支持预览、继续修改、打开位置和发送手机。修复应用继续编辑时工作目录不存在导致的错误。
- **更清楚的过程与控制**：执行记录收起展示；会话切换、暂停与停止状态更明确；操作手机时提供小窗预览，结束后不再残留“正在操作手机”。技能、记忆、模型和 MCP 能力入口归入 Amoo，实际可用性以手机接口与账号为准。
- **相册与存储扩容联动**：新增相册入口，按照片、视频及来源分类；过滤内部缩略图和回收站残留；已迁移原件与电脑预览关联。扩容配置、筛选、排序和文件状态更清晰。
- **手机日程与设备管理**：新增日历、闹钟入口；优化短信、通知、电话和应用列表，整理真实应用名称、图标及系统包展示。
- **扫码与自动重连**：修复伴侣扫码入口，改进已配对设备发现、动态端口更新、USB / 无线连接切换。适配固件可安装重启恢复组件；Android 重启后首次解锁仍由本人完成，路由器须允许设备互访。
- **背屏与投屏细节**：整理背屏预览、应用反馈和手机外框；投屏参数、画面旁控制栏与窗口状态衔接更清楚。
- **Google 服务诊断**：分开显示组件、权限、登录和设备证明状态。Google Play 安装或 GMS 修复不等于通过 Google 认证；X 原生 Google 登录的设备证明拒绝尚未解决。
- **性能与发布质量**：对话和大文件任务分流，减少重复读取与解析，非活动模块按需刷新；修复发布测试对开发机路径、固定手机和个人记录的依赖。

## 下载与升级

选择 `windows-x86_64`、`macos-arm64`、`macos-x86_64` 或 `linux-x86_64`，**完整解压**。保留 `tools`、`runtime`、`scripts` 等资源；不需要自行安装 ADB、Python、Java 或 Android Studio。每个安装包附 SHA-256。

旧版可使用客户端的 GitHub 更新入口；也可解压新版运行。用户设置和任务数据独立于程序目录。手机伴侣版本为 **0.1.32**；已自行组合 Neo 引擎的 APK 不应被普通公开 APK 覆盖，安装器会检查这一情况。

## 使用范围

- 主要适配 **STEPX Neo / PZ261A**。高级权限与重启恢复限定已核对的 Android 16 / 172 固件；其他固件不会按“相同型号”盲目写入。
- 普通 Android 不在本版客户端支持范围：设备识别当前限定 STEPX / PZ261A / pandora。手机伴侣需要 **Android 13+**。
- Windows x64 需要合适的 USB 驱动；macOS 未经 Apple 公证；Windows 未使用商业代码签名。Linux 发布包以 Ubuntu 24.04 为构建基线。
- Windows/macOS 的原生 CI、打包与运行依赖检查不等于已完成所有实体电脑和手机的图形界面验收。详见 [兼容性与本轮验证](https://github.com/xydzf520/stepx/blob/main/docs/CROSS_PLATFORM_0_2_50.md)。
- 普通对话默认沿用手机 Amoo 账号；自有模型与 GUI Agent 的模型服务分别配置、分别计费。公开伴侣包不包含许可未明确的 Neo 执行引擎。
