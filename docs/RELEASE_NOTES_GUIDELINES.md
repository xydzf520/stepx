# 更新日志、图文与视频规范

本项目首先用于作者找工作。更新弹窗首先让读者知道“作者正在求职、能做什么、如何联系或内推”，然后回答“更新对我有什么帮助、到哪里使用”。`CHANGELOG.md` 保存逐版本原始记录；客户端按最终用户场景整理累计变化，不能把提交标题或早期设计直接拼成更新页。

## 项目目的与顶部信息

这个项目用于作者找工作。更新页的第一组正文必须完整保留原有作者介绍、求职目的与经历、工作地区、原文、复制微信、邮箱、个人二维码、交流群二维码及用途、SkillForge 与 GitHub 入口。默认展开，不缩减、不改成折叠摘要、不拆到页面末尾。它们构成更新页默认首页，在同一弹窗内完整滚动阅读；设置 → 关于继续保留原有完整信息。

求职诉求必须是首屏最大的正文标题，原文用正常可读字号，联系微信是首要按钮；不能只做到“文字没删”，却把作者放进低对比灰色说明区。产品宣传标题不得比求职标题更抢眼。首页为完整求职信息，首页、重点更新和功能分类使用同一固定目录；不要再将作者与更新做成两个独立入口或长页面锚点。固定头部保留累计版本范围、回看路径及关闭控件，用户可直接切换到感兴趣的更新。普通阅读与分类切换不改变底层页面位置，不触发发送、拨号、模型生成或安装。

岗位和地区沿用作者原话；不擅自增加项目动机的解释句。「稍后在设置 → 关于回看」放在固定顶部，以正常字号、正常文字颜色显示，不放在底部灰色小字中。

过往身份与求职方向分开展示：保留“产品负责人 / 产品专家”，依据作者“产品岗或 AI 混合岗”的意向及后续岗位审查，明确为“产品岗 / AI 产品岗 / 产品与 AI 应用开发复合岗”，不把求职范围限定为管理岗位。完整求职段落和经历原文保持不变。

能力介绍须区分产品全流程交付与 AI 应用开发、评估：前者涵盖用户与业务调研、规划、体验设计与交互、AI 辅助前后端业务开发、测试、部署、运营迭代；后者说明业务适配、Agent 工作流、工具与数据接入、效果稳定性及用量成本。依据正式简历与项目实践描述，不堆工具名、不新增“全栈专家”等头衔，不把应用评估写成基础模型训练或未经证明的成本降幅。联系入口仍位于首屏，详细能力在原经历后补充。更新弹窗和设置 → 关于复用同一作者组件，避免文案不同步。

软硬件经历按作者要求集中表达“软硬件产品全流程交付”：能独立完成需求调研、规划、开发、联调测试与上线，并兼顾体验、稳定性、成本和后续迭代。不再列蓝牙、OTA、设备型号或音箱数量等功能清单，也不扩写电路、结构或制造能力。AI 辅助开发与 AI 应用评估继续由相邻段落说明，避免三段重复堆词；历史版本审计记录保留当时事实。

## 内容来源与审计

- `CHANGELOG.md`：每版日期、最终行为、修复、实际适用边界。
- `desktop/assets/release-notes/<版本>.json`：公开基线、用户价值排序、重点图文、分类场景、版本依据、使用条件和视频元数据。
- 同版本素材目录及 `sources.json`：真实截图/录屏版本、日期、演示数据性质、裁切/字幕与转码过程。复用旧素材保留原来源版本，不冒充最新录制。
- 跨版本回顾先核对 GitHub 最新公开发布与源码基线；两个历史没有共同祖先时做内容比较，不用本地提交数或局域网版本冒充公开发布进度。
- 每个场景必须有可核对的版本/实现依据。将同功能多次修改合成最终行为，区分新增与已有功能改进。被移除的倒计时、桌面十二次预算、旧存储硬上限等不能复活为当前卖点。
- 覆盖功能新增、交互改造、性能、数据保护与稳定性。原生 MCP 只是实现路径，先讲用户省下的操作，再说明必要条件。

## 内容层级与排序

累计回顾默认进入求职首页；统一目录提供重点总览、分类图文、内嵌演示、使用条件与完整逐版本记录。每次重新打开回到首页；切换分类从正文顶部开始，目录与窗口尺寸保持稳定。

顶部必须写明“累计更新：v起始版本 → v当前版本”，从本版更新元数据读取，不能只显示当前版本或把范围藏在视频旁；起点是内容对照基线，不是猜测用户上次安装版本。累计回顾保留公开版与开发版的区别。

- 第一层重点：独立桌面弹窗、实况胶囊、可自定义首页、最近文件。它们是核心使用路径，不能藏在“其他优化”。
- 第二层完整目录：搜索、消息电话、AI 成果、安排提醒、手机工具、性能、连接与数据保护。采用简短 SVG 分类入口，点击进入具体场景。
- 每个场景以收益标题、简短说明、1–3 个实际变化、就近的条件与功能入口组成。避免堆叠技术名词、重复计数和虚假进度图。
- 功能入口只导航到对应页或设置，不直接执行业务动作。逐版本记录按需加载，可返回总览；同一版本只自动提示一次。
- 参数、版本、能力边界随本版数据更新；标题不能残留上版开发版本号。

## 性能说明

性能独立成章，按用户感知描述：连接往返、中文/商店搜索、首页绘制、消息长列表、后台任务并行、数据库增量、缓存内存与背屏动画。

展示数字必须同时写明版本、数据量、环境、单位、指标和比较对象。历史微基准与同数据生产路径对照分开，不能将不同轮次数字拼接计算倍数。墙钟耗时不是 CPU、物理 I/O、帧率或整机速度。

例如 0.2.154 的 20,000 条合成记录热快照，改 1,000 条中位数 44.054 → 8.545 ms；它仍慢于同轮 JSON。单条增量的 0.059 ms 含 DTO 与读头成本，完整 JSON 的 3.229 ms 来自另一轮同数据三方对照。这些比较各自标明，不宣称“全面提速”。搜索文档部分 UI 线程汇总等剩余成本也要保留。

## 真实图文与窗口内视频

- 截图必须来自实现后的真实客户端隔离演示或经许可的真实系统页面。不能使用生成图伪造手机授权、对话、状态或操作成功。演示截图不代替端到端验收。
- 准备脱敏演示数据，不能截取真实聊天、验证码、号码、凭据或个人文件。截图保持比例，以裁切和代码绘制的指引突出重点；控件继续使用项目 SVG。
- PNG 宽 600–1600px、高 240–1000px，单张 ≤512KiB、一版总量 ≤3MiB；同时检查分类用图，不能只检查重点卡片用图。
- 视频只在操作连续性值得演示时加入。使用实际录屏、清晰中文章节和来源说明，不要求为每个修复硬做一段视频。
- **视频在更新窗口内播放、暂停、快跳与放大，不打开浏览器、不跳其他页面。** 默认不自动播放、不出声，无网络、跟踪脚本或额外播放器依赖。点击“看演示”是显式播放请求。
- 原生播放器复用已有 H.264 解码能力：单后台解码线程、单帧可替换缓存，暂停时不解码，关闭时释放工作线程，渲染不调用手机。失败原地显示原因和重试，其他图文仍可阅读。
- 离线 MP4 保留作为原始可分发视频，运行时使用相同录屏的有界 Annex B 文件；元数据必须匹配帧率、帧数、尺寸、章节与来源。单段 5–90 秒，MP4 ≤16MiB、原生流 ≤2MiB。依靠实际解码测试核对，不能用文件扩展名当可播放证明。

## 风格、交互与验收

- 统一 `R_PANEL` 圆角、单层 `popover_shadow`、细边框、安全内边距与克制类别色。作者信息、重点内容与次要说明层级清楚，不把所有内容做成同样的文字卡。
- 正文整体滚动，固定统一目录、版本范围、关闭与确认；宽屏图文并列，窄屏上下排列。加载媒体、换分类与后台数据刷新不改变原生窗口大小或焦点。
- 明确通知不是完整聊天历史；后台回复依赖应用入口，普通锁屏同步不等于锁屏 GUI；后台自动 AI 须当前账号通道验证授权；电脑双向音频目前限 Linux 和适配固件；原厂语音检查不等于通用离线 ASR/TTS 可用。
- 每次版本变更同步 Cargo、README、CHANGELOG、JSON、素材来源与审计报告。CI 运行 `python3 scripts/check-release-notes.py`，Rust 测试验证实际解码、完整分类、版本依据与异常数据。
- 实际验收浅/深主题、正常/窄/矮窗口、滚到底、完整作者信息、所有分类、关键功能入口、历史返回、原生视频播放/暂停/快跳/结束/关闭。区分模拟 UI 与真机结果，不替本轮未执行的真机用例背书。
- 提交按功能模块组织，记录验证与限制。修改更新说明不意味着获准公开发布全部源码或安装包。

## ADB 新手教程是独立需求

ADB 教程从连接设备的帮助入口打开，不混入更新页。一图一个动作，以真实系统画面加中文提示引导 USB 调试、授权与无线配对。官方示例必须标明来源、许可和机型差异，不能冒充当前设备截图。保留实际连接检测、安装/签名核验与失败原因，不为拍教程重置已有配对。
