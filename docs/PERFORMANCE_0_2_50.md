# 0.2.25 → 0.2.50 性能对照

2026-10-27，使用同一台 Linux x86_64 电脑（AMD Ryzen 9 7950X）、同一部 PZ261A（Android 16 / 172）与同一 USB 连接测量。以下是本次测量结果，不是所有设备、网络与账号的性能承诺。

## 结果

| 测量操作 | 0.2.25 中位耗时 | 0.2.50 中位耗时 | 耗时变化 | 每版样本数 |
| --- | ---: | ---: | ---: | ---: |
| Amoo 连续会话读取 | 730.13 ms | 345.48 ms | 减少 52.68% | 9 |
| 电话基础信息读取 | 401.82 ms | 275.43 ms | 减少 31.45% | 9 |
| 设备概要读取 | 151.05 ms | 134.14 ms | 减少 11.20% | 9 |
| 启动至窗口可见 | 118.66 ms | 122.01 ms | 增加 3.35 ms，基本持平 | 5 |

视频开头将前两项四舍五入为「约 53%」和「约 31%」。启动测量采用 15 ms 轮询，3.35 ms 差异低于轮询粒度，不据此宣称启动提速或显著退步。设备概要的样本范围重叠，也不作为主要宣传指标。

**这些是读取路径的耗时，不是模型 Token 生成速度、用户发问到回答完成的耗时，也不是全应用提速比例。** 此次不宣称「整体性能提升 53%」。

## 方法与复现边界

- 基线为 GitHub `v0.2.25`；新版为 `0216ce89518e9e9a8ee90ed9211963d699f2b103`，对应四平台 CI 的代码版本。
- 读取测试在两个版本的源码内加入同一份只读 [Rust 探针](performance/release_latency_probe.rs)，分别用各自发布配置、相同 Rust 工具链编译 Release。两版的发布优化选项与依赖保留各自实际版本，没有人为统一或额外加速。
- 三组版本顺序为旧→新、新→旧、旧→新。每个版本进程先完整预热一轮，再测三轮；每轮依次读取设备概要、电话能力和同一 Amoo 会话；轮间间隔 250 ms。共每项每版 9 个有效样本，所有请求均成功。
- Amoo 测试计时 `AgentBus::snapshot`，复用进程中的连接与正常缓存，测连续读取，不包含首次建立连接。两个版本返回的会话数均为 68；电话能力返回相同的 SIM 数量。未发送新消息、未请求模型生成。电话能力包括 SIM 与授权等基础信息，不是读取全部通话记录。
- 版本切换后的预热不计入结果，避免不同版本手机桥接文件首次准备影响比较。测试前备份手机桥接文件，结束后恢复；不清除账号或应用数据。
- 启动测试直接运行两版的 Linux 发布包，使用 `--demo --light` 与独立设置目录，保持相同 X11 环境。各预热一次，再交替启动 5 次，测进程创建到该进程的首个顶层窗口可见。它不是冷开机、首次下载依赖或手机数据全部载入时间。
- 本次仅在一台电脑/手机组合上测量；包含操作系统调度、手机响应与服务返回的波动，没有做统计显著性结论。Windows/macOS 不套用本机的百分比。

全部逐次耗时、最小值、最大值、顺序与版本信息见 [测量数据 JSON](performance/0.2.25-to-0.2.50.json)。数据中没有账号、会话标识、消息正文或设备序列号。

可把探针复制到所测版本的 `desktop/examples/release_latency_probe.rs`，设置 `STEPX_BENCH_DEVICE`、`STEPX_BENCH_SESSION` 与 `STEPX_ADB` 后编译运行。它从标准输入接收 `device_summary`、`phone_capabilities`、`amoo_snapshot`；`quit` 退出。请只使用本人已授权设备，准备桥接文件备份；首次连接与预热应单独记录。
