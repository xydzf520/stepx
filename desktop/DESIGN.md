# StepX Companion 设计规范

适用于 `desktop/src/ui/`；Android 伴侣沿用颜色、图标与圆角规范，字号和触控尺寸见 [手机端设计](../docs/design/android/README.md)。目标：像系统工具一样安静、可预期，信息密度适中，不做营销式表达。

## 1. 原则

1. **一屏一件事**：每个页面只解决一个任务，主操作只有一个（Primary 按钮每屏最多 1 个）。
2. **先内容，后装饰**：普通内容卡片不使用阴影、渐变、装饰符号和 emoji；层级靠留白、字重和分隔线表达。覆盖页面的浮层使用下文规定的轻阴影，区分前后层级。
3. **文案短而准**：按钮用动词（2–4 字），标题用名词；不写功能介绍，不写“智能”“旗舰”“矩阵”等修饰词。
4. **状态可见**：连接状态、进行中的任务、错误始终在固定位置（侧栏顶部、底部状态栏）。
5. **危险操作二次确认**：删除、发短信等不可逆操作使用行内确认条，不弹窗。

│          ├──────────────────────────────────────────┤
│ 导航      │                                          │
│          │ 内容区（左右 24px 内边距）                   │
│          │                                          │
│ 连接设备  │                                          │
│ 外观      ├──────────────────────────────────────────┤
│          │ ● 状态信息                                 │  28px
└──────────┴──────────────────────────────────────────┘

- 侧栏固定 216px；内容区最小宽度 760px。
- 列表/详情（短信）：左栏 296px，右栏自适应，各自滚动。
- 概览、应用、文件、连接为单列内容，最大可读宽度不限，靠面板分组。

## 5. 页面

对话输入区：文字、待发送附件和操作栏组成一个 16px 圆角容器，文字区域不再套独立边框。图片、文件、手机相册使用同一套 18px 线性图标和 32px 点击区域，悬停显示名称；发送按钮固定在容器右下方。附件在框内展示缩略图、名称、大小和移除入口。内容随实际换行增加高度，达到上限后在框内滚动。空内容、输入法候选未确认和等待回复时禁用发送；简洁、完整模式共享组件及草稿状态。

| 页面 | 结构 | 主操作 |
| --- | --- | --- |
| 概览 | 设备信息 → 指标（电量 / 温度 / 存储）→ 按键 + 截图 | 投屏 |
| Amoo | 对话记录（可滚动）→ 输入区（快捷提示 + 输入框） | 发送 |
| 短信 | 会话列表 ｜ 会话详情 + 输入区 | 发送（需确认） |
| 文件 | 路径 + 工具栏 → 文件表格（名称 / 大小 / 类型）→ 分页 | 上传 |
| 应用 | 搜索 + 范围 → 应用列表 | 安装 APK |
| 小工具 | 分类集合 → 工具详情 → 结果或行内确认 | 由所选工具决定 |
| 连接设备 | 已发现设备 → 无线配对（扫码 / 配对码 / IP）→ 已记住设备 | 连接 |

未连接设备时，依赖设备的页面统一显示空状态“未连接设备 / 连接设备”。

## 图标

产品界面统一使用 `assets/icons/` 中 24 × 24 网格、1.75 px 圆角线条的 SVG。导航图标固定为 20 px 容器，绘制尺寸为 16 px；普通操作以16–18px绘制，独立图标按钮保留完整点击区域与悬停说明。

按**使用位置**决定颜色，同一枚 `Bell` 在导航中为中性，在警告中才使用警告色：

| 用途 | 图形与颜色 | 实现 |
| --- | --- | --- |
| 导航、搜索、复制、刷新、发送、展开、文件操作 | 单色轮廓，跟随文字、选中、禁用状态；不各自固定颜色 | `ui_icon`／普通按钮 |
| 内容区模块、文件类型与功能分类 | 统一类型色与轻底色；图形、文字同时区分类别 | `content_icon`／`section_icon_badge`／`icon_style::content_style` |
| 成功、警告、错误、连接／完成状态 | 同一单色轮廓＋单一语义色；同时保留状态文字与不同形状 | `Palette::icon_foreground`，警告用`warning_text`，成功用`success_text` |
| 已知消息来源的通用占位 | 图形统一，来源颜色集中定义；未知来源不猜品牌 | `icon_style::channel_source_style`，所有页面共享 |
| 真实 StepX／Amoo／第三方 App 标识、文件缩略图 | 保留原图、原色及比例，不统一染色、不重画成通用轮廓 | `Image` |
| 图表、时间轴、分布与实况 SVG | 允许多色，仅用于表达类别和数据，颜色与图例对应 | 彩色 SVG／`Image`，不经过功能图标蒙版 |

`assets/icons/` 始终为**白色蒙版**，保留白色 stroke/fill；渲染器使用红通道作为alpha，再由调用点着色。不能将它们改为黑色、`currentColor` 或内置多色SVG。浏览器预览可用CSS蒙版着色，但不得把预览的着色方式写回生产资产。旧`stepx-companion.svg`不是当前安装品牌图，不应以它替换正在使用的PNG标识。

AI使用`Sparkles`，收藏使用五角`Star`；`GithubStar`只是星标指标，不是GitHub品牌Logo，保持单色。雨天与晴天、静音与响铃、解锁与锁定、未勾选与完成须有不同图形。`symbol`只解释控件的前导符号，不转换用户正文中嵌入的符号。

普通可操作小图标优先使用`text2`，不要使用浅色占位文字色；语义前景在明暗主题及常见弱底上按至少3:1的工程阈值检查。图表调色板、真实品牌图片及禁用透明度不随此前景规则改变。颜色不应成为唯一状态依据。

### 图形比例与安全边距

圆形、图标、流程节点和圆环保持等比，不能用`Image::stretch()`填满任意宽高的容器。固定图形空间不足时等比缩小；父容器额外的空间只作为留白。流程节点与文字同格，连接线独立伸缩；时间轴和柱图按实际可用宽度计算坐标及圆角，零值不画假进度。

卡片内部遵守12–16px安全内边距。长标题、说明、图例和操作应换行或上下排列；空间不足时由双栏切换为单栏，不能依靠裁剪隐藏越界文字。响应式布局须在测量约束改变、窗口变窄再变宽时重新选择分支。视觉验收包括980、1280、1720逻辑像素窗口，以及2倍缩放下3440×2304的实际截图与几何边界检查。

默认启动页为首页；读取设备信息前先绘制载入状态，设备发现和数据读取在后台运行。未知、载入中、读取失败和真实的零值应分别表示，不得用演示数据补足未知状态。

## Amoo Work

入口在“智能与开发”，紧接 Amoo；无参数启动仍为首页。工作视图默认只显示宽屏对话，“会话”和“工作文件”按需展开且互斥；“能力中心”集中模型、技能、智能体和 AI 应用目录。模型目录分页并支持搜索，明确区分已配置模型与仅有元数据的目录项，以及云 Amoo 和手机 OpenClaw 的来源。

模型回复、执行日志和实际产物分别展示。内部工具协议折叠为执行记录，不能将模型声称写入的文件当作已存在文件。安装技能展示发布者与安装目标，结果以手机回读为准。未知能力显示原因，不用示例模型、技能或任务填充。

回复使用原生 Markdown 格式，支持标题、粗体、列表、引用、代码、表格与可点击链接，复制保留原文。手机处理、桌面协作与图片创作为同一输入区的三种模式；手机附件不强制选择电脑目录，切到桌面协作时将附件复制到工作目录。图片须等待真实产物，展示缩略图、查看原图和另存为，不将任务下发回执作为生成成功。


## 首页资料到成果闭环 · 0.2.92

首页以“需要核对什么、下一步推进什么、已有成果在哪里”为顺序，新增一个工作区域承载四个视图，避免增加四套重复首页面板。空闲手机不占用执行卡片，待人工接管、失败和活动任务显示真实状态；按钮使用统一单色功能图标，状态颜色只表达实际进度。

### AI 来源、额度与当前周期整理 · 0.2.95

默认沿用手机账号。用量与可用额度以手机或所选模型服务为准，桌面不另设每日次数、剩余次数或固定的总结冷却时间；服务未返回的余额保持未知。服务返回的单次推理 Token 计数不等同于账户余额或账单。

“整理当前日周月”是用户发起的固定资料快照批次：逐份处理，同版本复用，遵循成果回手机设置；资料、设备或账号变化时停止旧快照请求。点击批量整理不等于开启跟随新资料的无人值守更新。当前手机原生后台通道尚未通过账号适配核验，界面明确保留这个限制，不提供必然失败的验证操作，也不回退独立 API。

保留串行执行、资料稳定等待、同版本去重与未知结果不自动重发，用于避免重复请求；这些机制不表示账户额度。模型产生的候选待办不自动变成用户承诺。讨论与摘要区分真实来源、AI 建议、用户维护的进展，以及尚待核实的资料。

资料发现只记录清单；明确点击处理后才取回正文。处理结果保留输入与正文摘要、解析方式和截短标记；OCR/ASR不冒充用户原话。生成方案通过同一事项来源与成果校验器，生成待办为候选；采纳和完成是用户操作，来源变化时保留旧记录并要求复核。延期保留原约定与原因，忽略可恢复，所有状态可撤销。

正文阅读使用统一的原生Markdown排版、限定阅读宽度及分页；回传的文件必须与当前预览字节一致，限定在当前设备和账号目录。账号变化、离线、停止或校验失败时，保留本地文件并报告真实状态，不显示已回传。

会前包只以日历具体实例或用户选择建立关联，原文、提取文本、用户行动记录分别标注来源；缺少议题、资料或确认状态时明确列出待补充项，避免将日程安排或模型建议写成完成事实。

### 内容区类别色 · 0.2.148

主导航与顶部导航继续使用中性单色。内容区使用蓝（文档、沟通、日程）、青绿（图片、表格）、紫（影音、应用、AI）、琥珀（文件夹、归档）、青（存储、工具）、玫瑰红（PDF）的固定映射。类型色不表示成功或失败；状态另有图形和文字。正文、通用操作和主按钮保持中性，真实应用图标与文件缩略图保留原色。浅色底仅限小图标容器，面板不着大面积彩色、不加阴影。

“文件与扩容”默认打开“最近文件”，提供综合、电脑、手机筛选；手机文件管理与扩容为同页的其他视图。最近文件从首页迁出时保留用户其他模块顺序与尺寸。

## 数据持久化与排障 · 0.2.150

### 改造前结构与清理边界（0.2.150 审查基线）

桌面业务数据主要是分模块 JSON 和 Markdown 文件，并没有统一的业务数据库。手机伴侣的消息也是 JSON；扩容模块另有 SQLite `expansion.db`。手机系统及第三方 App 的原始数据仍由其自身管理，MCP/伴侣提供的是获授权的数据视图，不能把同步副本视为完整原库。

Linux 默认配置位于 `~/.config/stepx-companion`（部分布局配置在 `~/.config/stepx`），状态位于 `~/.local/state/stepx-companion`，缓存位于 `~/.cache/stepx-companion`。部分模块再次拼接 `stepx-companion`，形成嵌套目录。环境变量/XDG 覆盖及其他平台规则以 `resources.rs` 为准；整理路径时须迁移旧目录，不可只更改拼接导致数据看似丢失。

| 数据 | 实现及现有保护 | 清理与剩余风险 |
| --- | --- | --- |
| 跨 App 证据、事项 | `context_ledger.rs`，设备/账号隔离；进程锁、文件锁、临时文件替换，损坏时保留原文件 | 证据按最近变更保留 90 天，最多 20,000 条，文件上限 64 MiB；仍需整份解析、合并、序列化，缺少字段查询索引 |
| 方案、日周月总结、预备材料 | 内容版本对应的 Markdown 文件；不同内容不覆盖，保护已编辑版本 | 证据过期不等于成果文件过期，历史版本持续累积；`context_ledger::clear` 会删除整个当前作用域，包括成果，不能拿来代替普通缓存清理 |
| 生成状态、待办、投递队列 | `context_pipeline.rs`、`action_ledger.rs`、`work_sync.rs`；状态、校验摘要和回执分开保存 | 投递队列保护未完成项并裁剪完成历史；文件与队列之间没有跨文件事务，崩溃可能留下孤立暂存文件，回收前必须检查引用和正在运行的任务 |
| 手机会话与通知 | `PushStore.java`，`im_threads.json` 与 `push_feed.json`；单写线程，约 1.8 秒合并写入 | 最多 100 个会话、每会话 100 条、500 条通知；两文件分别替换，没有共同事务；持锁序列化和写盘可能阻塞读写，突发退出可能损失尚未落盘的增量 |
| 手机扩容索引 | `ExpansionStore.java`，SQLite 表和路径索引 | 当前版本升级直接拒绝，需建立真实迁移路径；消息存储尚未复用它 |
| 通知中心状态 | `notification_center_state.rs`，JSON，已读/关闭 ID 各最多 2048，缓存历史最多 80 | 本版取消重复路径写入；ID 的裁剪顺序仍不是访问时间，长期使用需要按时间或源游标管理，避免旧通知重新出现 |
| 排障日志 | `diagnostics.rs`，本地 JSON，后台队列、批量写入、文件锁、敏感字段过滤 | 本版保留最近 30 天、最多 300 条；首次使用及每小时清理，容量满时保留最新记录；队列拥堵/写盘失败显示错误。尚未落盘的事件不承诺在强制结束进程后保留 |
| 图片预览 | `ui/preview_cache.rs`，按内容与作用域保存、检查图片尺寸 | 单作用域 512 MiB/2048 个对象，周期性回收；不等于所有作用域合计受同一预算约束 |
| 应用下载、图标、离线模型 | `app_store.rs` 等缓存目录 | 未发现覆盖所有下载包的统一空间回收；模型属于可重复使用的安装资产，不能与临时缩略图一样自动清除 |
| 搜索和最近文件 | `search.rs` 内存文档扫描；`recent_files.rs` 有界目录扫描 | 并非数据库全文索引，也非完整磁盘镜像；数据量增长会扩大字符串处理和重复遍历成本 |
| 模型服务凭据 | `studio_lab.rs` 的私有 JSON 配置；目录 0700、文件 0600 | 权限隔离不等同于加密；后续宜把密钥迁入系统凭据库，普通配置只保存引用，备份和日志排除密钥 |

“历史未齐”需要区分手机来源未开放、历史窗口裁剪、读取超时和本地保存失败。数据库改造能避免已获取记录被反复覆盖及裁剪，不能自动获得手机接口未提供的聊天历史；同步状态必须保留这些区别。

本机只读盘点（运行中的瞬时数值，文件逻辑大小，不是可释放空间承诺）：

- 缓存约 **1.55 GiB**：应用商店约 **1.09 GiB**，离线语音模型约 **464 MiB**。
- 状态目录约 **1.20 GiB**，其中两个旧验收程序副本约 **707 MiB**，不属于数据库，也未自动删除。
- 业务状态的嵌套目录约 **493 MiB**；一个上下文作用域已有 **12,649** 份复盘文件、约 **472 MiB**，证据 JSON 约 **2.6 MiB**。主要增长来自成果版本数量，单纯压缩 JSON 不能解决。
- 真实手机无线连接可用，但发布版伴侣禁止 `run-as`；上述手机存储结论来自代码审查，未宣称读取了手机私有数据库或完成其完整性检测。

### 本版已经实施

顶部取消“记录”，入口位于“设置 → 排障日志”；失败时底栏提供“原因与重试”。日志保留失败原因；当前进程中的读取失败关联原操作、目录及设备，重试前检查设备身份。发送、删除、安装等写操作只提供返回原操作入口，不重放旧命令。重启恢复日志不恢复可执行的重试命令。日志列表先渲染 30 条，按需查看更早记录。

`local_store.rs` 为小状态快照提供同目录唯一临时文件、文件同步、原子替换及 Unix 父目录同步，Unix 文件权限 0600；相同内容不重复写入。通知状态及通知设置已接入。它保证单文件替换完整，不提供多个写者读改写的合并事务，也不意味着所有历史 JSON 已完成迁移。

### 原定改造目标（实施情况见 0.2.153）

1. **先规范数据生命周期。** 设置、可重建缓存、同步源副本、用户成果、未完成任务、模型资产分别登记。清理页面按类别说明实际字节、保留规则和影响；成果、编辑版本、固定收藏、投递中材料不参加缓存清理。成果归档与删除来源记录分开，删除使用可恢复阶段。
2. **建立本地索引数据库。** 桌面优先把消息/会话、证据、来源游标、文件元数据、成果索引、关系、任务与投递回执纳入 SQLite；每条记录带设备/账号作用域、稳定源 ID、修订和删除标记。单写入队列、短事务、适当索引，读取分页，UI 不同步写盘。手机保持自己的数据库，跨设备交换增量，不共享数据库文件。
3. **文件保留在文件系统。** 图片、PDF、文档、导出成果按校验摘要寻址或保存原路径，数据库只记录引用、来源和版本。用户原文件不因索引清理而删除；数据库成功提交后再回收无引用的暂存文件，运行中任务持有使用标记。
4. **增量同步与版本收敛。** 用源游标/修订做幂等 upsert；一次事务落消息、已读状态与游标。摘要只有有效内容或证据版本变化时产生新版本，普通首页视图按需计算，避免每次轮询都留下完整复盘副本。相同来源名称、相同时间或相似正文不足以合并不同人的消息和图片。
5. **搜索改成索引查询。** FTS5 可负责全文检索，日期、应用、设备、类型用普通索引；中文须验证分词或 n-gram 策略，短词补充匹配，不能假定默认英文分词或 trigram 能覆盖单字/双字查询。文件监听与启动/定期核对结合，补偿离线期间漏事件。
6. **安全迁移与恢复。** 先备份并只读导入旧 JSON，校验条数、来源 ID、摘要和引用，做影子查询对比，再切换写入；迁移以版本事务执行，保留旧文件作为回退。用中断写入、磁盘满、并发实例、重复事件、损坏数据和重启恢复验证，不能只验证正常路径。

SQLite WAL 可改善读写并行，但仍要控制写事务时长、忙等待和 checkpoint，监测 WAL 增长；数据库应位于本机磁盘，不能直接放局域网共享盘。参考 [SQLite WAL](https://www.sqlite.org/wal.html)、[SQLite FTS5](https://www.sqlite.org/fts5.html)。手机单文件状态可使用 [Android AtomicFile](https://developer.android.com/reference/android/util/AtomicFile)，跨记录一致性则应使用数据库事务。

## 顶栏浮层规范 · 0.2.152

搜索浮框、消息中心、实况胶囊共用 `widgets::popover_surface`，以消息中心的单面板结构为基准。普通内容卡片保持平面；浮层只用轻阴影表达覆盖关系，不增加灰色背板、重复描边或错位面板。

| 项目 | 规范 |
| --- | --- |
| 表面 | 使用主题 `bg`，1px `border_strong` 边框，12px 圆角 |
| 阴影 | 单层；偏移 (0, 4px)，高斯模糊 σ=8px；浅色 `rgba(15,23,42,30/255)`，深色 `rgba(0,0,0,96/255)` |
| 渲染范围 | 原生 `spread_radius=24px` 是模糊采样边距，并非实体扩边；给足 3σ，避免阴影边缘被切成直线 |
| 安全边距 | 面板内边距至少 12px；列表可独立滚动，底部操作保持在内容区内 |
| 搜索对齐 | 输入框固定 320px，窄窗按实际空间收缩；浮框始终与输入框等宽、左边缘对齐 |
| 布局 | 阴影仅参与绘制，不参与宽高测量；不得用外边距或额外背景伪造阴影，不改变顶栏控件位置 |
| 裁剪 | 只裁剪内部滚动内容；不得裁剪完整浮层的阴影，底部异色区域使用内圆角 |
| 动效 | 搜索浮框保持 180ms 的透明度与轻微位移过渡；尊重减少动态效果设置，不推动页面内容 |

同一时间只允许一个顶栏浮层交互。点击消息中心、胶囊或更多操作，立即移交交互权并关闭搜索及其退场遮罩；重新点击搜索时关闭其他顶栏浮层。搜索词保留，关闭后不再接收键盘输入；Esc 或点击正文空白可关闭浮层。正文遮罩不得覆盖顶栏，不要求先关闭搜索再点第二次。阴影不扩展按钮的点击区域。

搜索来源、结果类型和消息中心分类使用同一套筛选按钮，直接置于浮层表面。选中态用按钮自身的轮廓和淡底表达。消息中心用来源头像或淡彩 SVG 区分来源，未读点和时间各占固定位置，悬停只改变背景色。

首页和日历页共用日期分类及图例。蓝点表示工作，青绿点表示生活，各最多一个。优先按标题显式标签、日历来源和明确的主题识别；用途不明的记录仍可查看。翻月淡入日期区，选日期淡入当天详情，按需停用动效。

### 桌面提醒窗口的稳定性

- 原生窗口尺寸由显示模式确定：完整预览 380 × 194px，隐藏正文 380 × 118px；不得使用上一帧文字或图片测量结果反向调整窗口。正文限制在预览区，底部操作保持 16px 安全边距。
- 桌面卡片沿用 `R_PANEL = 12px`，仅外层绘制背景，内部不得用矩形底色盖住圆角。顶栏菜单和关闭按钮为 32px 点击区，间距 4px，与卡片内容统一保留 16px 内边距；在小窗内不绘制越界提示层。
- 新消息更新当前卡片或进入队列，不移动当前窗口、不抢焦点、不打断中文输入。只有用户主动打开提醒菜单时可以切换至菜单高度。
- 弹窗回复与主窗口使用独立的输入焦点、候选文字及选择范围。后台刷新不能聚焦主窗口；延迟到达的键盘事件必须核对原通知身份，不能写入下一条通知或主窗口草稿。
- 显示、隐藏与关闭提醒不得激活其他窗口；只有点击回复框、查看详情等明确操作可以切换交互焦点。
- 队列按消息时间倒序，来电控制置顶。新事件到达时展示新卡片；相同快照的重复读取不翻页。同会话合并为一张卡，菜单、鼠标悬停、回复草稿及输入法组合期间先保持当前卡片，待交互结束再展示新事件。
- 红包使用 `red_packet_colors` 的暖红文字、浅红表面与细描边，配 SVG `Gift` 图标；使用原始红包消息标记识别，不能因群名、聊天提及或广告关键词染红。不增加窗口尺寸、动画抖动或自动领取行为；隐藏内容时不构建红包正文、图片及快捷操作。

验收需覆盖浅色与深色、普通与窄窗口：搜索→消息中心→搜索一次点击完成；关闭动画中也能切换；搜索宽度、顶栏位置不随打开、关闭或未读数变化而改变。


## 数据库与生命周期实现 · 0.2.153

此前 0.2.150 的表格是改造前基线。当前实现与验证详见 `docs/storage-optimization-0.2.153.md`；不把“采用数据库”视为所有操作必然更快，也不把获取不到的手机历史归因于数据库。

- 桌面业务库位于 `resources::user_state()/database/stepx.sqlite3`。跨 App 证据、行动账本、生成任务元数据、投递队列、排障日志已接入；顶层集合按作用域、分区、稳定 ID 分行保存，更新与删除使用同一事务。小偏好及凭据继续私有文件存储，图片、PDF、Markdown 和工作文件仍是原文件。
- WAL、FULL 同步、5 秒忙等待、外键与版本检查；自动 checkpoint 和维护使用不阻塞读者的方式。缓存连接、快照原文与单条编辑位置均有上限。读取缓存同时检查外部提交版本和本连接写入次数；单条编辑必须验证 JSON 值与记录 ID，不满足条件时走完整快照路径。
- 旧文件只读导入，解析后在事务内核对语义、记录条数和原件摘要，成功才标记完成。保留原文件，但迁移后的读取以数据库为准，避免旧文件覆盖新增记录。数据库损坏时保留现场，不静默创建空库。
- 搜索索引与文件预览为可重建缓存，和业务库分离。FTS5 使用中文单字/双字 n-gram，候选再经过原有匹配、来源筛选和排序，索引异常不阻断搜索。高命中率查询回到扫描路径；分页存储 API 不代表所有页面已经分页读取。
- 手机 `push.sqlite3` 独立存储获授权会话/通知视图，事务同时保存消息与游标；快照在状态锁内捕获，SQLite 提交在锁外完成；失败重试并暴露持久化异常。继续遵循原有 100 会话、每会话 100 条、500 通知窗口，不宣称完整第三方聊天数据库。`expansion.db` 由 v1 无损升级至 v2。
- 每小时后台维护；自动完整校验备份每天至多一份，保留最近 7 份，手动备份不自动删除。日志保留 30 天/300 条；文本预览保留最多 512 条/7 天；暂存只回收超过 7 天、没有运行中/未完成引用、目录内容可识别的项。
- 成果原文件、编辑版本、离线模型、正在传输的数据、旧迁移文件和手动备份均不参与自动缓存清理。相同证据、时间窗口、覆盖状态和内容摘要的复盘复用旧文件；不同版本和已编辑文件仍保留。
- 数据库备份先写私有临时文件，校验并同步落盘后无覆盖发布；失败副本不计入自动备份日期。
- `--restore-database` 只允许离线恢复到当前用户数据目录。恢复先校验备份，使用 SQLite backup API 包含已提交 WAL，保存旧库与 WAL/SHM，持久化恢复标记，最后替换。中断后普通启动拒绝覆盖，重新运行恢复可继续。数据库备份包含记录与文件引用，不包含文件实体或模型密钥；跨机器换路径不属于自动恢复范围。

性能验收同时列出快速查询、单条变更与批量变更。UI 使用后台工作线程，不在界面事件内执行迁移、索引构建、备份或数据库恢复。不会以降低落盘一致性来换取基准数字。
